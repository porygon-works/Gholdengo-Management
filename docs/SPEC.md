# Gholdengo 家計簿 仕様書（v3）

前の家計簿アーティファクトを置き換える、独立した家計簿Webアプリ。
計算はすべてアプリの計算エンジン（`src/engine/`）で行い、Notion・Claude には依存しない。

v3 では、入出金を **口座明細** と **クレカ明細** の2つの表に分けた（v2 までは `entries` 1つ）。

---

## 1. 全体の作り

```
Gmail ──(15分ごと)── GAS ──→ Supabase ←──→ Webアプリ（Vercel・PWA）
  三井住友の通知メール        明細・予算・目標      計算エンジン・画面
```

| 部品 | 役目 |
| --- | --- |
| Webアプリ（Vercel） | 画面と計算。スマホのホーム画面に追加して使う |
| Supabase | 明細・予算・目標・設定を保存。プロジェクト porygon-works の `ggmg` スキーマに置く。メールでログインし、本人だけが読み書きできる（RLS） |
| GAS | 三井住友カードの通知メールを読み、クレカ明細と請求額を Supabase に書く |

---

## 2. 前提

| 項目 | 決定 |
| --- | --- |
| 月の区切り | 暦の月（1日〜月末） |
| 今月の予算 | 給与 ＋ 追加予算 − 固定費 − 目標用マイナス（§5.1） |
| カード | 三井：月末締め・翌月26日払い（ふだん使う・メールから入る）／セゾン：月末締め・翌月4日払い（家賃とリボ）。土日祝は翌営業日。カードごとに設定で変えられる |
| 給料日 | 15日（土日祝は翌営業日） |
| 銀行 | 入出金の通知メールはないので、口座明細は手入力か定期マスタから作る。ずれたら残高を直す |
| 安全残高 | 0円（設定で変えられる） |

## 3. データ

### 3.1 口座明細（`account_entries`）

口座と財布のお金の動き。**入れたらすぐ残高が変わる**（予定は計上日が来るまで変わらない）。

| 列 | 値 | 説明 |
| --- | --- | --- |
| `account` | 口座／財布 | どこのお金か。財布はあまり使わなくてよい |
| `direction` | 入金／出金 | |
| `status` | 予定／確定 | |
| `group`（大費目） | 出金：変動費／固定費／立替／クレカ支払い／その他<br>入金：給与／追加予算／立替の返金／その他 | 予算での扱いを決める（§5） |
| `category`（費目） | 食料品・奨学金など | 出金の変動費・固定費のときに使う |
| `name`（名称） | 奨学金・三井 10月分など | 一覧に出す名前 |
| `memo` | | |
| `date`（計上日） | | 口座（財布）が動く日 |
| `amount`（金額） | | いつもプラス |
| `source` | 手入力／定期／クレカ請求／目標／移行 | どこから作られたか |
| `source_ref` | | 同じものを2回作らないためのキー（定期：`rec:ID:月`、クレカ請求：`bill:カード:引落日`） |
| `recurring_id`・`goal_id` | | 作った元 |
| `card` | | 大費目がクレカ支払いのとき、どのカードの請求か |
| `pair_id` | | ATM（口座→財布）のように2行で1つの動きのとき、相手の行 |
| `locked` | | 本人が直した。自動で作り直さない |

- **PayPayチャージ**：口座・出金・変動費（チャージした額を、その日に使ったものとして数える）
- **交通系を現金でチャージ**：財布・出金・変動費
- **ATMで引き出し**：口座・出金・その他 と 財布・入金・その他 の2行（`pair_id` でつなぐ）。予算は動かない
- **予定は計上日が来たら自動で確定**にする（定期・クレカ請求・目標から作ったもの）。手で入れた予定は、本人が確定にする
- 予定のまま計上日を過ぎた手入力の予定は、「日付が過ぎた予定」として出す（口座の今後の動きでは今日に数える）

### 3.2 クレカ明細（`card_entries`）

カードで使ったもの。**使っても口座はすぐには減らない**。予算が減り、来月の支払い予定（クレカ支払いの予定）が増える。

| 列 | 値 | 説明 |
| --- | --- | --- |
| `card` | 三井／セゾン | どのカードか（どの請求に入るか） |
| `status` | 予定／確定 | メールの速報も、実際に使ったものなので確定 |
| `date`（利用日） | | 締め日と合わせて、どの月の請求に入るかが決まる |
| `amount`（金額） | | |
| `group`（大費目） | 変動費／固定費／立替／分割 | §3.2.1 |
| `category`（費目） | 食料品など | 変動費・固定費のとき |
| `name`（名称） | 商品名など | |
| `shop`（店） | 利用した店名 | メールから入る。ルールで費目を決めるのに使う |
| `tatekae` | | 一部だけ立て替えたときの、立替の額（自分の分 ＝ 金額 − 立替額） |
| `source` | 手入力／カード速報／カード明細／定期／目標／移行 | |
| `source_ref`・`merged_into`・`not_dup`・`locked`・`recurring_id`・`goal_id` | | 重複の処理（§6）と、作った元 |

#### 3.2.1 大費目ごとの扱い

| 大費目 | 予算 | 請求（口座から出る額） |
| --- | --- | --- |
| 変動費 | 自分の分を数える | 入る |
| 固定費 | 固定費の見込みと比べる（§5.1） | 入る |
| 立替 | 数えない（全額が立替） | 入る。返してもらう分は口座明細の「入金・立替の返金」の予定として作れる |
| 分割（返済） | 数えない（目標用マイナスの中で払う） | 入る。毎月の返済額。目標マスタから予定を作る |
| 分割（購入） | 数えない | 入らない。リボ・分割で買った物。目標マスタの返済の残高に足す |

### 3.3 クレカの請求 → 口座明細

- カードごと・引落日ごとに、口座明細に「出金・**クレカ支払い**・予定」の行を自動で作る（名称「三井 10月分」）。
  - 予定のあいだは、金額 ＝ そのカードのその締め期間のクレカ明細（予定を含む。分割（購入）を除く）の合計。カードで使うたびに増える。
  - 確定の額が届いたら**確定**にする。三井はメール（お支払い金額のお知らせ）から自動で、セゾンや本人の報告は手で入れる。明細の合計との差を出す。
  - 引落日が来て確定の額がまだなければ、**見込みの額で確定**して口座から引く。あとから請求額が届いたら上書きする。
- クレカ支払いの行は予算に数えない（中身はクレカ明細で数えている）。

### 3.4 目標マスタ（`goals`）

| 列 | 返済の目標 | 積立の目標 |
| --- | --- | --- |
| `kind` | 返済 | 積立 |
| `name` | セゾンのリボ | 給料1か月分 |
| `card` | 返済するカード（空なら口座から振込） | ― |
| `balance`・`as_of` | 残高とその日 | ― |
| `target` | ― | 目標額 |
| `monthly` | 毎月の返済額 | 毎月積み立てる額 |
| `start_month`・`end_month` | 始める月・終わる月（空なら残高が0になるまで） | 始める月・終わる月（空なら目標額に届くまで） |
| `lumps` | 臨時の返済（日付・額・メモ。例：12/16に賞与から全額） | 臨時の積立 |
| `active` | 使う／止める | |

- **その月の目標用マイナス** ＝ その月に動いている目標の毎月の額 ＋ その月の臨時の額。予算マスタの「#目標用マイナス」で、月ごとに手で直せる。
- 返済の目標からは、毎月の返済の予定を作る。カードがあればクレカ明細（大費目：分割（返済））に、なければ口座明細（出金・その他）に入れる。臨時の返済は口座明細の出金の予定にする。
- 積立の目標は口座からお金を動かさない（口座に残しておく額として数える）。
- 「計画をつくる」（§5.6）は、目標マスタの毎月の額を決める画面。

### 3.5 予算マスタ（`budgets`）

| 列 | 説明 |
| --- | --- |
| `month` | どの月の予算か |
| `category` | 費目。`#目標用マイナス` はその月の目標用マイナスを手で直した値 |
| `amount` | 予算額 |

- ヘッダーの月を来月にすれば、来月の予算を見て直せる。
- 予算を入れていない月は、前の月の額を引き継ぐ（その月になったら、引き継いだ額をその月の分として保存する）。
- 予算の決め方：基本は前の月を引き継いでアプリで直す。Claude と相談して決めた額は、JSON にして「設定→データ」から取り込む。

### 3.6 そのほかのテーブル

| テーブル | 中身 |
| --- | --- |
| `recurring`（定期マスタ） | 給与・奨学金・家賃・サブスクなど。毎月の口座明細かクレカ明細の予定を作る（今月から5か月先まで） |
| `balances` | 残高を入れた・直した記録（日付・口座・財布・メモ）。いまの残高はここから数える（§5.5） |
| `rules` | お店→費目のルール |
| `settings` | カード・給料日・費目（大費目つき）・安全残高など |
| `review` | 要確認 |

### 3.7 取り込み（GAS）

| メール | 入れ方 |
| --- | --- |
| ご利用のお知らせ | クレカ明細に1件（三井・確定・カード速報） |
| ご利用明細のお知らせ | クレカ明細に全件（三井・確定・カード明細） |
| お支払い金額のお知らせ | その引落日の口座明細「クレカ支払い」を確定にして額を入れる |
| 読めなかったメール・取消や返品 | 要確認 |

- 費目はルールで決める。大費目は費目から決める（設定の費目の一覧）。
- 重複のまとめ（§6）はアプリを開いたときに計算エンジンが行う。

| `entries` の移動（ATM） | 口座明細の2行 |
| `card_bills` | 口座明細のクレカ支払い（確定） |

## 4. 画面

### 4.1 共通

- ヘッダー：画面の名前・表示している月（‹ ›）・メニュー
- フッター：ダッシュボード・明細・予定・設定

### 4.2 ダッシュボード

1. **今月の予算**と**残り予算**（大きく）。その下に「今月の予算の出し方」の表（給与 ＋ 追加予算 − 固定費 − 目標用マイナス ＝ 今月の予算）。タップで直す画面へ
2. **口座の今後の動き**（§5.5）
   - 表の一番上に、いまの口座残高
   - その下に、未来の口座明細（クレカ支払いの予定も含む）を日付の順に。次の給料日の前日まで
   - 一番下に合計の行（次の給料日の前日に残る額。マイナスなら赤）
   - 各行をタップすると詳細が開き、編集できる（クレカ支払いの行は、中身のクレカ明細と、確定の額の入力）
   - 「今月の引き落とし」はこの表にまとめた
3. **使ったものの入力**：費目・金額・払い方（三井／セゾン／現金／PayPay／口座）
4. **変動費・固定費の表**：費目ごとの今月の予算・使った＋予定・残り。それぞれ合計の行
5. **来月の支払い予定**（§5.6）：来月に口座から出るお金を大費目ごとの表で。タップでその大費目の明細の一覧

### 4.3 明細

- 口座明細とクレカ明細を切り替えて見る。費目ごと／日付ごとの表示
- タップで詳細・編集・削除

### 4.4 予定・設定・そのほか

- 予定：口座明細とクレカ明細の予定を月ごとに
- 設定：予算マスタ・目標マスタ・定期マスタ・カード・費目（大費目）・ルール・データ
- 口座と財布：残高を直す・ATM・直した履歴
- 計画をつくる：目標マスタの毎月の額を決める

## 5. 計算式

### 5.1 今月の予算

```
今月の予算 T = 給与 ＋ 追加予算 − 固定費 − 目標用マイナス
```

| 予算の元 | 出し方 | 直し方 |
| --- | --- | --- |
| 給与 | その月の口座明細の入金のうち、大費目が給与のもの（予定を含む） | 口座明細を直す |
| 追加予算 | その月の口座明細の入金のうち、大費目が追加予算のもの（予定を含む） | 口座明細を直す |
| 固定費 | 予算マスタにある固定費の費目の合計（見込み）。予算がない費目は、その月の定期マスタの額、それもなければその月の固定費の明細の合計 | 予算マスタ |
| 目標用マイナス | 目標マスタから（§3.4） | 予算マスタの `#目標用マイナス` |

### 5.2 残り予算

```
変動費で使った額 U ＝ その月のクレカ明細の変動費（自分の分）＋ その月の口座明細の変動費の出金（口座・財布）   … 確定
変動費の予定 P    ＝ 同じものの予定
固定費の超過      ＝ 固定費の費目ごとに、使った＋予定（クレカ明細・口座明細）が見込みをこえた分の合計
残り予算 R        ＝ T − U − P − 固定費の超過
```

- 費目ごとの予算・残り・1日に使える額は v2 と同じ（予備 ＝ T − 予備以外の変動費の予算の合計。未分類は予備で数える）。

### 5.3 クレカの請求の額

```
見込み（カード c・引落日 d）＝ 締め期間（d の月 − 引き落とす月数 の1日〜締め日）の c のクレカ明細の金額の合計
                               （予定を含む。分割（購入）を除く。立替もそのまま入る）
請求額 ＝ 確定していれば確定の額、なければ見込み
```

### 5.4 いまの口座残高

```
いまの口座残高 ＝ 最後に入れた（直した）口座の残高 ＋ そのあと今日までの口座明細（口座）の 確定 の 入金 − 出金
```

- 財布も同じように数える。
- 残高を直すと、アプリの計算との差を記録に残す。

### 5.5 口座の今後の動き

```
いまの口座残高
± 明日〜次の給料日の前日の、口座明細（口座）の予定と確定（計上日の順。クレカ支払いの予定を含む）
＝ 次の給料日の前日に残る額
```

- 予定のまま計上日を過ぎた手入力の予定は、今日に数える。
- 給料日の前日に残る額が安全残高を下回るなら赤にし、いくら足りないかを出す。

### 5.6 来月の支払い予定

来月に口座から出るお金を、大費目ごとの表で出す（行をタップすると、その大費目の明細の一覧を開く。明細をタップすると詳細）。

| 大費目 | 中身 |
| --- | --- |
| 固定費 | 来月の請求に入るクレカ明細の固定費（自分の分）＋ 来月の口座明細（口座）の固定費の出金 |
| 変動費 | 同じく変動費 |
| 分割の返済 | クレカ明細の分割（返済）＋ 返済の目標から作った口座の出金 |
| 立替 | クレカ明細の立替 ＋ 一部だけ立て替えた分 ＋ 口座の立替の出金 |
| その他 | 口座のその他の出金 |
| クレカの確定の額との差 | 請求額が確定していて、明細の合計と違うとき |
| 計 | 来月に口座から出るお金の合計 |

- 「来月の請求に入るクレカ明細」は、来月に引き落とされる締め期間のもの（三井・セゾンとも月末締め・翌月払いなので、今月使ったもの。予定を含む）。
- 口座明細のクレカ支払いの行は数えない（中身のクレカ明細で数えている）。

### 5.7 目標の見通しと計画

- 目標マスタの毎月の額と臨時の額で、返済の目標の残高が0になる月と、積立の目標が目標額に届く月を出す（36か月まで。利息・手数料は入れない）。
- 「計画をつくる」：毎月の額から／達成したい月から（v2 と同じ考え方）。「この計画にする」で目標マスタの毎月の額と期間を直す。

## 6. 重複の処理（クレカ明細）

### 6.1 信頼度

```
予定 ＜ 手入力 ＜ カード速報 ＜ カード明細
```

新しい明細が入ったとき、それより信頼度の低い明細の中から相手を探す。見つかったら、信頼度の低いほうを吸収する（`merged_into` に吸収先を入れる。消さない）。

### 6.2 自動でまとめる条件

信頼度の低い明細から順に処理する（手入力→予定、速報→手入力、明細→速報、と段を上がるように吸収する）。
候補の中でいちばん信頼度の高いものが1件だけのとき、自動でまとめる。

| 相手 | 条件 |
| --- | --- |
| 実際の明細（手入力・速報） | 金種が同じ・金額が同じ・日付の差が3日以内 |
| 定期のお金の予定 | 日付の差が7日以内で、金額の差が20%以内（3,000円未満はぴったりのときだけ）。費目が同じか、どちらかが未分類 |
| 定期のお金の予定（ヒントつき） | 上に加えて、予定に「お店の名前のヒント」があり明細のお店にそれが入っていれば、費目が違ってもまとめる（定期代の Suica が「交通」で入るときなど） |
| 一回きりの予定（手で入れた予定など） | **自動ではまとめない**。上と同じ条件に合えば要確認に回し、「予定『○○』の支払いですか？」と聞く（同じ費目で似た金額の別の買い物と取り違えやすいため） |

まとめたときの値：

- 金額・日付・お店：信頼度の高い明細の値
- 費目：本人が入れた（直した）値、なければ予定の費目、なければルールの費目
- 買った物・メモ・立替額：空いていれば低いほうから引き継ぐ
- **カード速報→カード明細**：お店の名前が「Mastercard加盟店」でも、明細側の本当のお店の名前に置き換わる

### 6.3 要確認に回す

- 候補が2件以上ある
- 金額は同じだが日付の差が4〜7日
- 手入力の明細と、日付が近く金額が少し違う（10%以内）。メールの明細どうしで金額が違うものは別の買い物とする
- 一回きりの予定と、条件に合う明細（§6.2）

要確認の画面では「同じもの（まとめる）」か「どれとも別のもの」を選ぶ。「別のもの」にした組み合わせは、二度と候補に出さない。

### 6.4 そのほか

- まとめたあとでも、明細画面から「まとめを取り消す」ができる。
- クレカで手入力したのに7日たってもメールで入ってこない明細は、要確認に出す。

## 7. 作り方

- Vite＋React＋TypeScript、PWA（電波がなくても最後のデータを表示）。Supabase の設定がなければ「お試しモード」（データはその端末のブラウザの中）で動く
- 計算エンジン・重複処理・営業日の計算は、画面と分けた関数にして Vitest でテストする
- Supabase のテーブル定義は `supabase/migrations/` に置く。表はすべて `ggmg` スキーマに作る（`public` は使わない）
- GAS のコードは `gas/` に置く（clasp で上げるか、コピーして貼る）
- Vercel がビルドしてデプロイする。Supabase の URL と公開キーは Vercel の環境変数に入れる
- 今のアーティファクトのデータは、アプリで取り込める JSON に変えて渡す（家計のデータなのでリポジトリには入れない）。取り込みはアプリの「設定→データ」から、ログインした本人の権限で行う

## 8. この版でやらないこと

- 銀行口座の入出金の自動取り込み（通知メールがないため）
- PayPay のチャージの自動取り込み（通知メールがないため、手で入れる）
- 2人以上での利用
