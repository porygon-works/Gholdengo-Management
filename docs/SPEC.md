# Gholdengo 家計簿 仕様書（v2 案）

石原家計簿アーティファクトを置き換える、独立した家計簿Webアプリ。
計算はすべてアプリの計算エンジン（`src/engine/`）で行い、Notion・Claude には依存しない。
見た目と使い方は、今のアーティファクトと同じ感じにする。

---

## 1. 全体の作り

```
Gmail ──(15分ごと)── GAS ──→ Supabase ←──→ Webアプリ（Vercel・PWA）
  三井住友の通知メール        すべての入出金       計算エンジン・画面
```

| 部品 | 役目 |
| --- | --- |
| Webアプリ（Vercel） | 画面と計算。スマホのホーム画面に追加して使う |
| Supabase | すべての入出金・予算・設定を保存。メールでログインし、本人だけが読み書きできる（RLS） |
| GAS（Google Apps Script） | 三井住友カードの通知メールを読み、Supabase に書く。使うのは無料の時間主導トリガーだけ |

Claude は使わない。読めなかったメールはアプリの「要確認」に出す。

---

## 2. 前提

| 項目 | 決定 |
| --- | --- |
| 月の区切り | 暦の月（1日〜月末） |
| 使える額 | 資産の残高から逆算する（§5） |
| 費目予算 | 全費目に予算を持つ。予備は残りが自動で入る |
| カード | 三井住友（Amazonマスター）：月末締め・翌月26日払い（土日祝は翌営業日） |
| 給料日 | 15日（土日祝は翌営業日） |
| 銀行 | みずほ銀行。通知メールはないので、残高はアプリで入れる |
| リボ・分割 | 返済額は「返済」費目の支出。リボで買った物は予算外 |
| 安全残高 | 0円（設定で変えられる） |

## 3. 画面

### 3.1 共通

- **ヘッダー**：画面の名前、表示している月（‹ › で月を移動）、ハンバーガーメニュー
  - メニューの中身：残高を入れる・要確認・目標・設定・ログアウト
- **フッター**：画面を切り替えるタブ
  - ダッシュボード・明細・予定・設定

### 3.2 ダッシュボード

1. 表示している月と、月を移動するボタン
2. **今月使える予算**（総予算 T）と**残り予算**（R）
3. **使ったものの入力フォーム**（その場で入れられる）
   - 費目・金額・金種（クレカ／現金／PayPay／交通系／ポイント）
   - 日付は今日が初めから入っている。お店とメモは開いたときだけ入れる
4. **費目ごとの予算と残り**（変動費は1日に使える額も）
5. 要確認の件数（タップで要確認一覧へ）
6. 口座残高の見通し（次のカード引落日までの、いちばん少ない残高とその日）

### 3.3 明細

- 費目ごとに、使ったものの一覧を見られる（タップで開く）
- 各明細には状態を出す：予定／速報／確定
- 明細をタップすると、費目・金額・メモの直し、立替額の入力、削除（手入力のものだけ）ができる
- 未分類の明細は一番上にまとめて出す

### 3.4 予定（入出金の予定）

- 給与・賞与・急な入金・大きな出費などの予定を一覧で見る
- 予定の追加・直し・**確定にする**（金額を入れて「確定」を押す）
- 定期のお金（§4.4）から作られた予定もここに出る

### 3.5 設定

- **予算**：費目ごとの予算（前の月から引き継ぐ。予備は自動）
- **見込み額**：給与の見込み・賞与の見込み（月と金額）・固定費の見込み
- **定期のお金**：家賃・奨学金・共済・通信・サブスクなど（名前・金額・日・金種・費目）
- **資産**：安全残高・目標残高（25.5万円）
- **お店→費目のルール**：自動で覚えたものの一覧と直し
- **借金**：リボ・分割の残高と最低返済額

### 3.6 その他（メニューから）

- **要確認**：重複の候補・読めなかったメール・照合できなかった速報
- **目標**：① リボ・分割の残高を0にする ② 引落日に口座が足りない月を0にする ③ 給料日前日の残高を目標以上にする
- **残高を入れる**：口座・現金・PayPay の今の残高

## 4. データ

### 4.1 すべての入出金は1つのテーブル（`entries`）

予定・速報・確定・手入力・収入・お金の移動まで、すべて `entries` に入れる。

| 項目 | 内容 |
| --- | --- |
| `kind` | 支出／収入／移動（口座→現金、口座→PayPay など） |
| `status` | 予定／速報／確定 |
| `date` | 使った日（予算に数える日） |
| `amount` | 金額（いつもプラスの数で持つ） |
| `method` | クレカ／現金／PayPay／交通系／ポイント／口座 |
| `category` | 費目（収入と移動はなし） |
| `shop`・`item`・`memo` | お店・買った物・メモ |
| `tatekae` | 立替額（予算に数えない分） |
| `source` | 手入力／カード速報／カード明細／定期／移行 |
| `source_ref` | 取り込み元のID（メールのID＋何件目か）。同じものを2回入れないためのもの |
| `merged_into` | 重複として吸収された先の明細。吸収されたものは計算に入れない |
| `recurring_id` | 定期のお金から作られたときの元 |

ほかのテーブル：

| テーブル | 中身 |
| --- | --- |
| `balances` | 残高の報告（日付・口座・現金・PayPay） |
| `card_bills` | カード請求額（引落日・金額）。メールから自動で入る |
| `recurring` | 定期のお金（名前・種類・金額・日・営業日のずらし方・金種・費目・開始月・終了月） |
| `budgets` | 費目予算（月・費目・金額） |
| `rules` | お店→費目のルール（お店の名前の一部・費目） |
| `debts` | リボ・分割（名前・残高・時点・最低返済額・メモ） |
| `settings` | 安全残高・目標残高・給与の見込み・費目の一覧など |
| `review` | 要確認（種類・対象の明細・本文・解決したか） |

### 4.2 金種ごとの「予算から減る日」と「資産から減る日」

| 金種 | 予算から減る日 | 資産から減る日 | 入り方 |
| --- | --- | --- | --- |
| クレカ | 使った日 | 翌月26日（翌営業日） | メールから自動 |
| 現金 | 使った日 | 使った日 | 手入力 |
| PayPay | 使った日 | 使った日 | 手入力 |
| 交通系 | チャージした日（チャージ額＝交通費） | クレカでチャージ：翌月26日／現金でチャージ：その日 | クレカでのチャージはメールから自動（モバイルSuicaは自動で「交通」） |
| ポイント | 使った日 | 減らない | 手入力 |

- **資産**は、口座・現金・PayPay の合計で考える。
  - ATMの引き出しや、口座からPayPayへのチャージは「移動」なので、使える額は変わらない。
  - 移動は記録しなくても計算は合う。財布ごとの残高を見たいときだけ入れる。
- **ポイント払い**は、予算では使った額に入るが、資産は減らない。そのため、その分だけ使える額が自然に増える。

### 4.3 取り込み（GAS）

15分ごとに、まだ読んでいない三井住友カードのメールを読む。

| メール | 入れ方 |
| --- | --- |
| ご利用のお知らせ（`statement@vpass.ne.jp`） | 1件を `status=速報` で入れる。日時・お店・金額を読む |
| ご利用明細のお知らせ（同じ送り主） | 1通に入っている全件を `status=確定` で入れる |
| お支払い金額のお知らせ | `card_bills` に引落日と金額を入れる |
| 読めなかったメール | `review` に件名と本文の最初を入れる |

- 費目は `rules`（お店の名前の一部→費目）で決める。合わなければ「未分類」にする。
- アプリで費目を直すと、そのお店の名前でルールを自動で覚える（「Mastercard加盟店」のように中身が分からない名前は覚えない）。
- 同じメールを2回読んでも、`source_ref` が同じなら入れない。

### 4.4 定期のお金

- `recurring` から、各月の給与（収入）・家賃など・通信やサブスクの予定を自動で作る（`status=予定`、今月から3か月先まで）。
- 日付が土日祝なら、設定に従って前か後ろの営業日にずらす（日本の祝日・振替休日に対応）。
- 給与と賞与は、設定の見込み額で予定を作る。入金があったら予定画面で「確定」にして金額を直す。

## 5. 計算式

### 5.1 予測資産 A(t)

```
A(t) = 最新の残高報告（口座＋現金＋PayPay）
     ＋ 報告日より後〜t までの収入（予定・確定）
     − 報告日より後〜t に資産から減る支出（予定・速報・確定。§4.2の日付で数える）
```

- 同じ日のなかでは、収入を先に、支出をあとに数える。
- カード請求額（`card_bills`）があるときは、その引落日のクレカ支出は明細の合計ではなく請求額で数える。
- 重複として吸収された明細（`merged_into` があるもの）は数えない。

### 5.2 今月の残り予算 R

```
H = 今月クレカで使った分の引落日（翌月26日・翌営業日）
R = min { A(t) : 今日 ≤ t ≤ H } − 安全残高
```

- 「今月まだ使っていい額を今日ぜんぶ使っても、今月分の引落日まで一度も安全残高を下回らない額」。
- 予定は A(t) に入っているので、R は予定を引いた後の自由に使える額。
- R がマイナスなら、このままだと引落日までに足りなくなる。強く警告する。

### 5.3 今月使える予算 T

```
使った額 U = 今月の支出（速報・確定。金額−立替額。予算外と吸収されたものは除く）
予定 P    = 今月のまだ済んでいない支出の予定
T = U + P + R
```

### 5.4 費目ごと

```
予備の予算 = T − 予備以外の費目予算の合計
費目の残り = 予算 − 使った額 − 予定
1日に使える額 = floor(費目の残り ÷ 月末までの日数（今日を含む）)   … 残り ≤ 0 なら 0
```

- 未分類は、分類されるまで予備として数える。
- 予備がマイナスなら「費目に割り振りすぎ」と出す。
- 返済の予算が最低返済額より少なければ警告する。

### 5.5 先の月と過ぎた月

- **先の月**：今月の R を今日すべて使ったことにして、同じ計算を続ける（3か月先まで）。目標②の判定に使う。
- **過ぎた月**：予算と実績を比べるだけにする（T＝費目予算の合計）。

## 6. 重複の処理

### 6.1 信頼度

```
予定 ＜ 手入力 ＜ カード速報 ＜ カード明細（確定）
```

新しい明細が入ったとき、それより信頼度の低い明細の中から相手を探す。見つかったら、信頼度の低いほうを吸収する（`merged_into` に吸収先を入れる。消さない）。

### 6.2 自動でまとめる条件

次の3つがすべてそろい、かつ候補が1件だけのとき：

- 金種が同じ（予定は金種を問わない）
- 金額が同じ（予定は ±20% まで）
- 日付の差が3日以内（予定は7日以内）

まとめたときの値：

- 金額・日付・お店：信頼度の高い明細の値
- 費目・買った物・メモ・立替額：本人が入れた値を残す
- **カード速報→カード明細**：お店の名前が「Mastercard加盟店」でも、明細側の本当のお店の名前に置き換わる

### 6.3 要確認に回す

- 候補が2件以上ある
- 金額は同じだが日付の差が4〜7日
- 日付は近いが金額が少し違う（10%以内）

要確認の画面では「同じもの（まとめる）」か「別のもの」を選ぶ。

### 6.4 そのほか

- まとめたあとでも、明細画面から「まとめを取り消す」ができる。
- クレカで手入力したのに7日たってもメールで入ってこない明細は、要確認に出す。

## 7. 作り方

- Vite＋React＋TypeScript、PWA（電波がなくても最後のデータを表示）
- 計算エンジン・重複処理・営業日の計算は、画面と分けた関数にして Vitest でテストする
- Supabase のテーブル定義は `supabase/migrations/` に置く
- GAS のコードは `gas/` に置く（clasp で上げるか、コピーして貼る）
- Vercel がビルドしてデプロイする。Supabase の URL と公開キーは Vercel の環境変数に入れる
- 今のアーティファクトのデータを `entries` などに移すスクリプトを作る

## 8. この版でやらないこと

- みずほ銀行の入出金の自動取り込み（通知メールがないため）
- PayPay の自動取り込み
- 2人以上での利用
