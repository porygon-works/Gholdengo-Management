# Gholdengo 家計簿 仕様書（v5）

独立した家計簿 Web アプリ。計算はすべてアプリの計算エンジン（`src/engine/`）で行う。
v5 は「**予算残額**（今月あといくら使えるか）」と「**余裕額**（使い道の決まっていないお金がいくらあるか）」の2つを主役にした版。どの数字もタップすると式と中身の行がたどれる。

- 設計の理由と例：[docs/superpowers/specs/2026-10-23-v5-yoyuugaku-design.md](superpowers/specs/2026-10-23-v5-yoyuugaku-design.md)（設計書）。この仕様書と食い違うときは設計書に合わせて両方直す
- Claude との書き出し・取り込み：[docs/OPS.md](OPS.md)

---

## 1. 全体の作り

```
Gmail ──(15分ごと)── GAS ──→ Supabase ←──→ Webアプリ（Vercel・PWA）
  三井住友の通知メール        明細・予算・計画      計算エンジン・画面
```

| 部品 | 役目 |
| --- | --- |
| Webアプリ（Vercel） | 画面と計算。スマホのホーム画面に追加して使う |
| Supabase | 明細・予算・計画・設定を保存。プロジェクト porygon-works の `ggmg` スキーマに置く。メールでログインし、本人だけが読み書きできる（RLS） |
| GAS | 三井住友カードの通知メールを読み、クレカ明細と請求額を Supabase に書く |

画面は「ホーム・明細・見通し・計画・設定」の5つ。

## 2. 前提と用語

| 項目 | 決定 |
| --- | --- |
| 月の区切り | 暦の月（1日〜月末） |
| カード | 設定で持つ（名前・締め日・引落日・引落月。あとから足せる）。1枚目は「いつものカード」で、メールから入り、見通しで予算の残りをこの請求に乗せる。土日祝は翌営業日 |
| 給料日 | 設定の日（土日祝は翌営業日）。給与の予定がない先の月は、設定の給与の見込みを使う |
| 銀行 | 入出金の通知メールはないので、口座明細は手入力か定期マスタから作る。ずれたら残高を直す |
| 財布 | 持たない。ATM で引き出したら、その日に使ったもの（費目「現金」）にする |

| 用語 | 意味 |
| --- | --- |
| 目安額 | 給与の見込み − 固定費 − 借入の毎月の返済 − 貯蓄計画の毎月の積立額 |
| 予算 | その月に決めた額。決めていなければ、月の初めの目安額をその月の予算として保存したもの |
| 予算残額 | 予算 − 使った額 − 予定 − 固定費の超過 |
| 余裕額 | 口座残高 ＋ 未入金給与 ＋ 未回収立替 − 支払予定額 − 確保額 |
| 支払予定額 | ① 未払いのクレカ請求 ＋ ② 今月の口座の予定 ＋ ③ 今月の予算残額と固定費の未使用分 ＋ ④ 借入残高 ＋ ⑤ 先の月の追加予算 |
| 確保額 | 使う日のある貯蓄計画（大きい買い物など）の積立額の合計 |
| うち貯蓄 | 使う日のない貯蓄計画（生活費1か月分など）の積立額の合計。余裕額に入ったまま、ホームに別に出す |
| 借入 | リボなど。返済先ごとに借入残高と毎月の返済額を持つ |
| 返済計画 | 返済先をまとめ、期日にまとめて返す計画 |
| 貯蓄計画 | 目標額にためる計画。使う日があってもなくてもよい |

## 3. データ

### 3.1 口座明細（`account_entries`）

口座と財布のお金の動き。**入れたらすぐ残高が変わる**（予定は計上日が来るまで変わらない）。

| 列 | 値 | 説明 |
| --- | --- | --- |
| `account` | 口座／財布 | どこのお金か。財布はあまり使わなくてよい |
| `direction` | 入金／出金 | |
| `status` | 予定／確定 | |
| `group`（大費目） | 出金：変動費／固定費／立替／クレカ支払い／その他<br>入金：給与／賞与／立替の返金／その他（追加予算は前の版の行を読むためだけに残す） | 予算での扱いを決める（§5） |
| `category`（費目） | 食料品・奨学金など | 出金の変動費・固定費のときに使う |
| `name`（名称） | 奨学金・三井 10月分など | 一覧に出す名前 |
| `memo` | | |
| `date`（計上日） | | 口座（財布）が動く日 |
| `amount`（金額） | | いつもプラス |
| `source` | 手入力／定期／クレカ請求／目標・計画（前の版）／移行 | どこから作られたか |
| `source_ref` | | 同じものを2回作らないためのキー（定期：`rec:ID:月`、クレカ請求：`bill:カード:引落日`） |
| `recurring_id`・`goal_id` | | 作った元 |
| `plan_id`・`debt_id`・`plan_role`・`budget_month` | | v4 の計画の取引の名残。v5 では数えない（切り替えの「v4 から引き継ぎ」で、予定の行は消し、確定した行はつながりを外す） |
| `card` | | 大費目がクレカ支払いのとき、どのカードの請求か |
| `pair_id` | | ATM（口座→財布）のように2行で1つの動きのとき、相手の行 |
| `locked` | | 本人が直した。自動で作り直さない |

- **PayPayチャージ**：口座・出金・変動費（チャージした額を、その日に使ったものとして数える）
- **交通系を現金でチャージ**：財布・出金・変動費
- **ATMで引き出し**：口座・出金・変動費・費目「現金」の1行。引き出した日に使ったものとして予算に数える（財布の残高は持たない）
- **予定は計上日が来たら自動で確定**にする（定期・クレカ請求から作ったもの）。手で入れた予定は、本人が確定にする
- 予定のまま計上日を過ぎた手入力の予定は、「日付が過ぎた予定」として出す（口座の今後の動きでは今日に数える）

### 3.2 クレカ明細（`card_entries`）

カードで使ったもの。**使っても口座はすぐには減らない**。予算が減り、来月の支払い予定（クレカ支払いの予定）が増える。

| 列 | 値 | 説明 |
| --- | --- | --- |
| `card` | 三井／セゾン | どのカードか（どの請求に入るか） |
| `status` | 予定／確定 | メールの速報も、実際に使ったものなので確定 |
| `date`（利用日） | | 締め日と合わせて、どの月の請求に入るかが決まる |
| `amount`（金額） | | |
| `group`（大費目） | 変動費／固定費／立替／リボ／分割（旧） | §3.2.1 |
| `category`（費目） | 食料品など | 変動費・固定費のとき |
| `name`（名称） | 商品名など | |
| `shop`（店） | 利用した店名 | メールから入る。ルールで費目を決めるのに使う |
| `revolved_at` | | リボに回した日（v5）。この日から借入残高に入る |
| `tatekae` | | 一部だけ立て替えたときの、立替の額（自分の分 ＝ 金額 − 立替額） |
| `source` | 手入力／カード速報／カード明細／定期／目標／移行 | |
| `source_ref`・`merged_into`・`not_dup`・`locked`・`recurring_id`・`goal_id` | | 重複の処理（§6）と、作った元 |

#### 3.2.1 大費目ごとの扱い

| 大費目 | 予算 | 請求（口座から出る額） |
| --- | --- | --- |
| 変動費 | 自分の分を数える | 入る |
| 固定費 | 固定費の見込みと比べる（§5.1） | 入る |
| 立替 | 数えない（全額が立替） | 入る。返してもらう分は口座明細の「入金・立替の返金」の予定として作れる |
| 分割（旧） | 数えない | 数えない。前の版の毎月の返済額の行（返済は借入の毎月の返済で数える） |
| リボ | v5 でリボに回したもの（`revolved_at` がある）はその費目で数える。前の版の分割（購入）は数えない | 入らない。そのカードの借入の借入残高に足す（§5.4） |

### 3.2.2 明細を消す

- メールや定期・目標から作った明細（`source_ref` がある）は、行を残して `deleted` にする。計算にも画面にも出さない。こうしないと、メールの取り込み（直近3日を読み直す）や予定づくりで、また同じものが作られる。
- 手で入れた明細は行ごと消す。
- クレカ明細を消すと、その明細にまとめた明細（速報・手入力・予定）も一緒に消す。ATM の口座明細は相手の行も消す。

### 3.3 クレカの請求 → 口座明細

- カードごと・引落日ごとの請求を、口座明細の「出金・**クレカ支払い**」の行として出す（名称「三井 10月分」）。
- **保存するのは、お金が動いたときと、額が確定したときだけ**。まだ確定していない先の請求は保存せず、毎回クレカ明細から出す（見込み）。
  - 見込み ＝ そのカードのその締め期間のクレカ明細（予定を含む。リボを除く）の合計。カードで使うたびに増え、中身がなければ出ない。
  - 確定の額が届いたら、確定の行として保存する。三井はメール（お支払い金額のお知らせ）から自動で、セゾンや本人の報告は手で入れる。明細の合計との差を出す。
  - 引落日が来て確定の額がまだなければ、**見込みの額で確定の行**を作って口座から引く。あとから請求額が届いたら上書きする。
  - 見通しでは、いつものカード（設定の1枚目）の請求の見込みに、その月の予算残額（使っていない予算）を足す（§5.6）。
  - 借入の毎月の返済のうちカードの請求と一緒に引き落とされるものは、請求の行には入れず、借入の行として数える（§5.4）。
- クレカ支払いの行は予算に数えない（中身はクレカ明細で数えている）。

## 4. 画面

### 4.1 共通

- **計算した数字は、タップすると内訳が出る**（式と、その中身の行）。式の名前もタップでき、明細の行まで追える。
- 押せるところの印：内訳が出る数字は数字のすぐ右に金の「›」、開いて見る・直すもの（明細の行・計画・返済先など）は右端に灰の「›」。押せないものには付けない。
- 色はサーフゴーから取る（金・黒・赤・銀）。明るい画面と暗い画面の両方。
- 見込みは点線の枠と「見込」の印。予定は「予定」の印。
- 保存の前に、余裕額・その月の予算残額・口座残高の最低がどう変わるかを出す（比べ）。余裕額がマイナスになっても止めず、注意だけ出す。

### 4.2 ホーム

1. **予算残額** と **余裕額**（同じ大きさで並べる）
   - 予算残額：使った額の棒、残りの日数、1日あたり
   - 余裕額：60日の動きの小さい線、60日後の見込み、うち貯蓄
2. 口座残高と、60日内で一番少なくなる日と額（マイナスなら赤）。押すと見通しへ
3. 費目別残額（こえた費目は赤）。押すとその費目の明細へ
4. 支出入力（費目・金額・払い方。払い方は設定のカード・PayPay・口座・現金）
5. 最新明細

### 4.3 明細

- クレカ明細と口座明細を切り替える（1つの表に混ぜない）。費目別か日付別。
- クレカ明細の画面で：リボ化・リボ解除（そのカードの借入があるとき）、計画連携（使う日のある貯蓄計画にひも付ける）、立替（返してもらう予定を口座明細に作れる）。
- 口座明細の画面で：分割（1行を費目ごとに分ける）。

### 4.4 見通し

- 線グラフ：口座残高と余裕額。過去は記録から、先は見込み（予算どおりに使う前提）。1か月・3か月・全期間。y 軸の目盛りの数字は出さない（なぞるとその日の額）。
- その下に、これからの入出金（口座の行。月ごと、行ごとの残高つき）。

### 4.5 計画

- **返済計画**：期日、返済額・期日の口座残高・返済後の最低残高の3つ、返済先の一覧（借入残高・毎月の返済額）。返済先は「返済先追加」から入れる。返済計画に入っていない返済先は「返済計画なし」にまとめて出す。
- **貯蓄計画**：積立額と目標額の棒、達成見込、使う日、毎月の積立額、賞与配分の予定、確保額か余裕額に含むか。中で積立追加・賞与配分・取崩を記録する。

### 4.6 設定

予算（月の予算と目安額の式、費目別予算）・給与と賞与・定期・お店のルール・区分（費目と大費目の名前）・口座とカード（給料日・給与の見込み・カード）・データ（v4 から引き継ぎ、Claude 相談の取込、書き出し）。

## 5. 計算式

式の理由と、月の変わり目・給料日・引落日で余裕額が跳ねないことの例は、設計書 §2 にある。

### 5.1 口座残高

最後に入れた残高の記録 ＋ そのあと今日までの口座明細 − 借入の毎月の返済（カードの請求が確定の額で入っているときは、その中に入っているので引かない）。

### 5.2 目安額と予算

- 目安額 ＝ 給与の見込み（その月の給与の口座明細、なければ設定の給与の見込み）− 固定費（固定費の費目の予算の合計）− 借入の毎月の返済 − 貯蓄計画の毎月の積立額（目標額に届いた分は0）。
- 予算 ＝ その月に決めた額。決めていなければ月の初めに目安額を保存し、それを使う（あとで見込みが変わっても動かない）。決めた額か目安額かまだかを `source` で持つ。

### 5.3 予算残額と費目別残額

- 予算に数える出費：クレカ明細の変動費・固定費・v5 でリボに回した明細（その費目で）、口座明細の出金の変動費・固定費。重複でまとめられた明細・消した明細・計画にひも付けた購入・v4 の計画の行は数えない。立替は自分の分だけ。
- 費目別残額 ＝ 費目の予算 − 使った額 − 予定。使いすぎは予備で埋めず、その費目をマイナスにする。費目の一覧にない費目と未分類は予備で数える。
- 予算残額 ＝ 予算 − 変動費の使った額 − 予定 − 固定費の超過（固定費の費目で予算をこえた分）。

### 5.4 借入

- 借入残高 ＝ 最後の記録 ＋ そのあとリボに回した明細（`revolved_at` の日から。カードごとに、そのカードの最初の借入に足す）− そのあとの毎月の返済。
- 毎月の返済：カードの請求と一緒なら、そのカードの引落日。口座からなら `pay_day`（土日祝は翌営業日）。返済計画の期日の前日まで。期日に残りをまとめて返す（借入残高は0になる）。
- 利息・手数料は見込まない。カードのサイトの額に直したときの差を「借入残高の修正」として内訳に出す。

### 5.5 余裕額

```
余裕額 ＝ 口座残高 ＋ 未入金給与 ＋ 未回収立替 − 支払予定額 − 確保額
```

| 部品 | 中身 |
| --- | --- |
| 未入金給与 | 今月の給与のうち、まだ口座に入っていない分（給料日より前か、給料日以後の残高の記録がまだないとき） |
| 未回収立替 | 口座明細の「立替の返金」の予定 |
| ① 未払いのクレカ請求 | 利用日が今月末までで、まだ引き落とされていないクレカ明細（リボ・分割（旧）を除く） |
| ② 今月の口座の予定 | 今月末までの口座明細の予定の出金（借入の返済の行は除く） |
| ③ 今月の予算残額 | 予算残額（0 より小さくしない）＋ 固定費の予算のうち、まだ明細のない分 |
| ④ 借入残高 | 借入の全部（§5.4） |
| ⑤ 先の月の追加予算 | 今月より先の月で、決めた予算が目安額をこえている分の合計 |
| 確保額 | 使う日のある貯蓄計画の積立額（§5.7） |

来月以降の給与・予算・固定費は今日の余裕額に入れない（⑤だけが例外）。

### 5.6 見通し

- 今日より後の口座の動き：口座明細の予定（日付が過ぎた予定は今日に数える）、給与の予定がない月の給与の見込み、カードの請求（見込みは、いつものカードにその月の予算残額を足す）、借入の毎月の返済とまとめての返済。
- その日の余裕額は、その日の口座残高の見込みで §5.5 を出す。
- 返済計画の3つ：返済額（期日の前日の借入残高の見込み）、期日の口座残高（返す前）と返せるか、返済後の最低残高（期日から60日で口座残高が一番少なくなる日と額）。

### 5.7 貯蓄計画

- 積立額 ＝ 毎月の積立額（始める月から毎月1日。使う日のある計画は使う日の月まで）＋ 積立追加 ＋ 賞与配分（賞与が確定してから）− 取崩 − ひも付けた購入。目標額をこえては積まない。
- 使う日のある計画（`buy`）：積立額を確保額として余裕額から引く。買った明細をひも付けると、その明細は予算に数えず積立額から払ったものにする（差は余裕額が受ける）。
- 使う日のない計画（`save`）：毎月の積立額は目安額から引くだけで、積立額は余裕額から引かない（うち貯蓄）。予算を使い切っても、積立額の分だけ余裕額が毎月上がる。
- 完了にした計画の積立額は0（余裕額に戻る）。

## 6. 重複の処理（クレカ明細）

### 6.1 信頼度

```
予定 ＜ 手入力 ＜ カード速報 ＜ カード明細
```

新しい明細が入ったとき、それより信頼度の低い明細の中から相手を探す。見つかったら、信頼度の低いほうを吸収する（`merged_into` に吸収先を入れる。消さない）。

### 6.2 自動でまとめる条件

信頼度の低い明細から順に処理する（手入力→予定、速報→手入力、明細→速報、と段を上がるように吸収する）。
候補の中でいちばん信頼度の高いものが1件だけのとき、自動でまとめる。

| 相手 | 条件 |
| --- | --- |
| 実際の明細（手入力・速報） | 金種が同じ・金額が同じ・日付の差が3日以内 |
| 定期のお金の予定 | 日付の差が7日以内で、金額の差が20%以内（3,000円未満はぴったりのときだけ）。費目が同じか、どちらかが未分類 |
| 定期のお金の予定（ヒントつき） | 上に加えて、予定に「お店の名前のヒント」があり明細のお店にそれが入っていれば、費目が違ってもまとめる（定期代の Suica が「交通」で入るときなど） |
| 一回きりの予定（手で入れた予定など） | **自動ではまとめない**。上と同じ条件に合えば要確認に回し、「予定『○○』の支払いですか？」と聞く（同じ費目で似た金額の別の買い物と取り違えやすいため） |

まとめたときの値：

- 金額・日付・お店：信頼度の高い明細の値
- 費目：本人が入れた（直した）値、なければ予定の費目、なければルールの費目
- 買った物・メモ・立替額：空いていれば低いほうから引き継ぐ
- **カード速報→カード明細**：お店の名前が「Mastercard加盟店」でも、明細側の本当のお店の名前に置き換わる

### 6.3 要確認に回す

- 候補が2件以上ある
- 金額は同じだが日付の差が4〜7日
- 手入力の明細と、日付が近く金額が少し違う（10%以内）。メールの明細どうしで金額が違うものは別の買い物とする
- 一回きりの予定と、条件に合う明細（§6.2）

要確認の画面では「同じもの（まとめる）」か「どれとも別のもの」を選ぶ。「別のもの」にした組み合わせは、二度と候補に出さない。

### 6.4 そのほか

- まとめたあとでも、明細画面から「まとめを取り消す」ができる。
- クレカで手入力したのに7日たってもメールで入ってこない明細は、要確認に出す。

## 7. 作り方

- Vite＋React＋TypeScript、PWA（電波がなくても最後のデータを表示）。Supabase の設定がなければ「お試しモード」（データはその端末のブラウザの中）で動く
- 計算エンジン・重複処理・営業日の計算は、画面と分けた関数にして Vitest でテストする
- Supabase のテーブル定義は `supabase/migrations/` に置く。表はすべて `ggmg` スキーマに作る（`public` は使わない）
- GAS のコードは `gas/` に置く（clasp で上げるか、コピーして貼る）
- Vercel がビルドしてデプロイする。Supabase の URL と公開キーは Vercel の環境変数に入れる
- Claude と相談して決めたことは `gholdengo-ops-v2` の JSON にして「設定→データ」から取り込む（docs/OPS.md）。家計のデータはリポジトリに入れない

## 8. この版でやらないこと

- 銀行口座の入出金の自動取り込み（通知メールがないため）
- PayPay のチャージの自動取り込み（通知メールがないため、手で入れる）
- 財布（現金）の残高の管理（ATM で引き出した時点で使ったものにする）
- 利息・手数料の前もっての計算
- 確保額を自動で差し引く仕組み（取崩順・取崩不可）
- 2人以上での利用
