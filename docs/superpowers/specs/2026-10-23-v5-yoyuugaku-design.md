# 設計書：余裕額を中心にした家計簿（v5）

2026-10-23 作成。この設計書が決まったら、`docs/SPEC.md` を v5 として書き直し、それを正とする。
数字の例はすべて作り物（このリポジトリは公開されている）。

---

## 1. 目的とわけ

### 1.1 何を作るか

今月使える額を予算として管理し、カードの明細を取り込んで自動で予算から引き、「いくら使ったか・あといくら使えるか」をひと目で分かるようにする家計簿。
そのうえで、カードごとに後から来る請求、リボなどの借入、賞与でまとめて返す計画を、**少ない考え方で一本につなげる**。

### 1.2 なぜ作り直すか

v4 までで、やりたいことの一つ一つはできている。しかし組み合わせた結果、

- 画面に出る言葉が多い（今月の予算・残り予算・目安・計画の分・口座残高・実質残高・確保額・予備・たまる額・請求の見込み など）
- どの数字がどう計算されたのか、なぜその表にその行があるのかが分からない
- 予算の決め方・リボの二重計上・請求の見込みを、継ぎ接ぎで何度も直してきた

という状態になった。**計算の筋道が見えないこと**が一番の問題で、説明文をあちこちに書いて埋めるのも嫌（うるさい）。

### 1.3 だれが・いつ使うか

本人1人。スマホ（ホーム画面に追加したアプリ）で、次の4つの場面で開く。

| 場面 | 見たいもの |
| --- | --- |
| 何か買いたいとき | 今月の予算があとどれくらいあるか（全体と費目ごと） |
| お金を使う予定ができたとき | その予定を入れたら、この先どうなるか |
| 自動の取り込みを確かめるとき | メールから入った明細が反映されたか、反映後の予算 |
| 何か買ったとき（気が向いたら） | 手で入れる。カード・iD の分は、メールから入った明細と同じなら1つにまとまる |

### 1.4 成功の条件（使い始めて1か月後）

1. 上の4つの場面が、迷わずすぐできる（不便がない）。
2. 予算残額（全体・費目別）・余裕額・確保額・口座残高の先の動きが見られ、どの数字もタップで理由をたどれる。
3. **12月の賞与でリボを本当に全部返せる。** 返済の計画で「賞与からの配分を入れると期日にそろうか」が見え、そのとおりに返せる。

## 2. 中心の考え方

### 2.1 お金を3つに分ける

口座と財布にあるお金（と、今月これから入る給与）は、意味で3つに分かれる。

| 名前 | 意味 |
| --- | --- |
| **支払予定額** | 出ていくことが決まっているお金。まだ引き落とされていないカードの請求、今月の予算の残り、今月これから出る固定費、借入残高（リボ） |
| **確保額** | 目的があって取っておくお金。計画（購入・貯蓄）ごとの入れ物に入っている |
| **余裕額** | 決まった使い道がないお金。見て安心するためのもの。急な出費があれば予算に足し、大きい買い物をしたくなれば計画に入れる。動かさなくてもよい |

### 2.2 余裕額の式

```
余裕額 ＝ 手元資金 ＋ 未入金給与 ＋ 未回収立替 − 支払予定額 − 確保額
```

| 部品 | 中身 |
| --- | --- |
| 手元資金 | いまの口座残高 ＋ 財布残高 |
| 未入金給与 | 今月の給与のうち、まだ口座に入っていない分（予定の額） |
| 未回収立替 | 立て替えて、まだ返してもらっていない額（口座明細の「立替の返金」の予定） |
| 支払予定額 | ① 未払いのクレカ請求：利用日が今月末までで、まだ引き落とされていない明細（予定の明細も含む。リボに回した分は除く）<br>② 今月末までの口座明細の予定の出金（固定費など。借入の返済の行は除く）<br>③ 今月の予算残額（使っていない予算。0 より小さくはしない）<br>④ 借入残高（リボなど、借りているお金の全部。毎月の返済・まとめての返済の行は①②に入れず、ここだけで数える）<br>⑤ 先の月の追加予算：今月より先の月で、決めた予算が目安額をこえている分の合計（余裕額から先の月の予算に足した分） |
| 確保額 | 返済以外の計画（購入・貯蓄）の積立額の合計 |

- **月で組にする**：その月の給与を、その月の予算・固定費・計画の積立にあてると考える。今月カードで使った分は来月引き落とされるが、今月の支払予定額に入る。
  - 15日の給与を「先月の支払い用」と考えても「今月用」と考えても、余裕額の値は同じになる（両方を数えているため）。
  - こうするので、毎月1日（予算が支払予定額に入る日）にも、15日（給与が入る日）にも、カードの引落日にも、余裕額は跳ねない。
- **借りたお金は自由ではない**：借入残高は全部支払予定額に入る。リボに回しても余裕額は増えない。返し終わるまで、余裕額は低く、またはマイナスに見えることがある。
- **返済の計画は積立額を持たない**（§3.3）。返す先の借入残高がすでに支払予定額に入っているので、ためる入れ物を作っても余裕額には意味を持たないため。
- **先の月の予算に余裕額から足したら、足した時点で今日の余裕額から引く**（⑤）。何月の予算に足しても、「余裕額から足したのに数字が変わらない」ということが起きない。
- 来月以降の給与・予算・固定費は、今日の余裕額には入れない（⑤だけが例外）。見通しのグラフの先の部分で使う。

### 2.3 余裕額が動くとき・動かないとき

| できごと | 余裕額 |
| --- | --- |
| 予算より使いすぎた（予算残額が0をこえて使った分） | 減る |
| 月が終わって予算が余った（その月の予算残額が支払予定額から外れる） | 増える |
| 予算を目安額より多く決めた／余裕額から予算に足した | 減る |
| 予算を目安額より少なく決めた | 増える |
| 計画（購入・貯蓄）に入れた | 減る |
| 賞与・臨時の入金が確定した | 増える |
| 給与が見込みと違った | 差だけ動く |
| 借入残高をカードのサイトの額に直した（利息・手数料など） | 差だけ動く（内訳に「借入残高の修正」として出る） |
| 購入の計画で、実際の値段が積立額と違った | 差だけ動く |
| 月の初め（予算を目安額どおりにしたとき） | 借入の毎月の返済の分だけ増える（目安額から返済の分を引いていて、その分だけ借入残高が減る見込みのため） |
| 給与が入った・カードが引き落とされた・リボに回した・リボを返した（毎月の返済も、まとめての返済も） | 変わらない |

### 2.4 例（作り物の数字）

給与 25万（15日）・家賃 8万（セゾン、翌月4日払い）・予算 17万（三井、翌月26日払い）・賞与 30万（12/10）。リボの毎月の支払いは省く。
11/1 の口座 30万、余裕額 5万。

| 日 | できごと | 口座残高 | 余裕額 |
| --- | --- | ---: | ---: |
| 11/1 | 11月の分（給与の見込み・家賃・予算）が入る | 30万 | 5万 |
| 11/4 | 10月の家賃の引き落とし | 22万 | 5万 |
| 11/15 | 給与 | 47万 | 5万 |
| 11/20 | 11月の家賃をリボに回す（12/4 の請求から外れ、借入残高 +8万） | 47万 | 5万 |
| 11/26 | 10月に使った分の引き落とし | 30万 | 5万 |
| 12/4 | セゾンの請求：家賃はリボなので 0 | 30万 | 5万 |
| 12/10 | 賞与 | 60万 | 35万 |
| 12/15 | 給与 | 85万 | 35万 |
| 12/26 | 11月に使った分の引き落とし | 68万 | 35万 |
| 12/27 | リボをまとめて返す | 60万 | 35万 |

この表は、図にしたページ（会話の中で見せたもの）と同じ数字。

## 3. お金の流れ

### 3.1 入ったお金は、いったん全部余裕額に入る

給与・賞与は、入ったら（給与は月の初めに見込みとして）いったん余裕額に入り、そこから配る。

```
給与・賞与 → 余裕額 → 固定費・借入の毎月の返済・予算・計画の積立
```

- 月の初めに、その月の給与の見込みが入り、決まった額が自動で配られる（固定費・借入の毎月の返済・計画の毎月の積立額）。
- **予算の目安額 ＝ 給与の見込み − 固定費 − 借入の毎月の返済 − 計画の毎月の積立額**。
  - 予算を目安額どおりに決めれば、余裕額は借入の毎月の返済の分だけ増える（借入残高が減るため）。それ以外は変わらない。
  - 目安額より多く決めればその分減り、少なく決めればその分増える。**予算を決めることの影響が、余裕額の増減として見える。**
- 賞与も余裕額に入る。そこから計画に配分する。

### 3.2 予算

- 区切りは暦の月（1日〜月末）。いまと同じ。
- 月の予算は、その月に決めた額。決めていなければ、**その月の初めに計算した目安額をその月の予算として保存する**（あとで給与や固定費の見込みが変わっても、その月の予算は動かさない。差は余裕額が受ける）。
- 固定費は予算の外（目安額を出すときに引く）。ただし固定費が見込みをこえたら、こえた分は予算残額から引く（v4 と同じ。使うお金は予算を通す）。ホームの費目別残額の最後に、固定費の合計（見込みと使った額）を1行出す。
- 費目別の予算は、一度決めたら毎月そのまま使う。変えたい月だけ直す。
- **予備** ＝ 月の予算 − 費目別の予算の合計。費目に割り当てていない、月の中の急な出費の枠。
- 費目で予算をこえて使ったら、その費目をマイナスのまま赤く出す。**予備から自動で埋めない。** 全体でいくら使えるかは、月の予算残額（合計）で見る。
- **使うお金は必ずどこかの月の予算に入れる。** 余裕額から直接使う道は作らない。
  - 予定（例：来月の結婚式 3万）は、その月の予算の費目か予備に予定として入れる。
  - その月の予算残額が足りなくなるときは「足りない ¥◯◯ を余裕額から◯月の予算に足しますか？」と聞く。「はい」なら月の予算が増え、余裕額が減る。

### 3.3 計画

計画は「名前・目標額・期日（なくてもよい）」を持つ入れ物。

| 種類 | 期日 | 目標額 | 例 |
| --- | --- | --- | --- |
| 返済 | まとめて返す日（なくてもよい） | 期日の借入残高の見込み | リボを12月の賞与で全部返す |
| 購入 | 使う日 | 決めた額 | 大きい買い物 |
| 貯蓄 | なし | 決めた額 | 生活費1か月分 |

- 購入・貯蓄の計画にお金が入る道は3つ。
  1. **毎月の積立額**：月の初めに自動で配る（予算の目安額が減る）。
  2. **余裕額から入れる**：好きなときに手で入れる。
  3. **賞与からの配分**：まだ入っていない賞与に「この賞与から ¥25万 をこの計画に」とひも付けて予定しておく。賞与が確定した時点で積立額に入る（日付ではなく賞与の確定にひも付ける）。賞与の額が違ったときは賞与の額を直すだけでよく、差は余裕額が吸収する。
- 購入・貯蓄の計画の画面では「積立額（確定）＋ 配分の予定 ＝ 期日にそろうか」を出す。
- 購入の計画で実際に買ったときは、その明細（カードなど）を手で計画にひも付ける。ひも付けた明細は予算に数えず、積立額から払ったものとする。値段が積立額と違えば、差は余裕額が受ける。余ったら残りは余裕額に戻る。
- **返済の計画は積立額を持たない。** 計画の画面には、期日について次の3つを出す。
  1. 返す額の見込み（期日の借入残高の見込み）
  2. その日の口座残高の見込み（賞与などを入れた額）と、それで返せるか
  3. 返した後の余裕額
  - 返すための節約は、予算を余らせて余裕額を増やすことで表れる（返した後の余裕額が増える）。
  - 返済の計画での「賞与からの配分」は、「この賞与でまとめて返す」という印にする（余裕額は動かない）。
  - 期日に口座残高が足りない見込みなら、計画の一覧と見通しで知らせる。
- **給与の先食いをやめる**のも、特別な機能ではなく貯蓄の計画（生活費1か月分）として作る。その計画がいっぱいになれば先食いはなくなっている。

### 3.4 借入（リボ）

- 返す先ごとに借入残高を持つ。カードのサイトで見た額に直せる。
- 毎月の返済は、口座から出る予定として持つ（カードの請求と一緒に引き落とされるものは、どのカードかを持つ）。返すと手元資金と借入残高が同じだけ減る。返済の行は借入残高（④）だけで数え、①②には入れない。
- 利息・手数料は前もって計算しない。毎月の返済は全額が借入残高を減らすものとして見込み、カードのサイトで見た額に直したときの差を「借入残高の修正」として内訳に出す（余裕額はその差だけ動く）。
- **リボに回す**：カードの明細（例：11月の家賃）を選んで「リボに回す」と、その明細はそのカードの請求から外れ、借入残高に足される。
- まとめて返すと、借入残高が0になる。
- お金の動き1つにつき、行は1つ（二重に数えない）。v4 で何度も直した「計画の支払いとカードの分割（返済）の二重計上」が起きない形にする。

### 3.5 余裕額がマイナスになるとき

| 場面 | どうするか |
| --- | --- |
| 自分の操作（予算に足す・計画に入れる）で、0以上だった余裕額がマイナスになる | マイナスになる分について、確保額があれば「◯◯から ¥△△ を差し引きます。よろしいですか？」と、どの計画からいくら引くかを出して確認する。確保額もなければ、注意を出したうえで許す |
| 操作の前からマイナス（リボの残高があるときなど） | 確認は出さず、「余裕額がマイナスです（¥…）」と注意だけ出して許す。確保額を崩させない |
| 使いすぎ（取り込みなど）で自然にマイナスになった | 余裕額を赤く出し、「確保額から差し引く」ボタンを出す。押すかは本人が決める |

- 確保額から差し引く順は、計画ごとに前もって決めておく（**取崩順**）。
- **取崩不可**の印を付けた計画からは自動で差し引かない。それしか残っていなければ、差し引かずに注意だけ出す。
- 余裕額のマイナスは「計画どおりにいかなくなった」という早めの知らせ。口座残高がある日にマイナスになる（分割やリボが要るかもしれない）のは別のことで、見通しのグラフで分かる。2つは別のものとして見せる。

### 3.6 クレカの請求（口座のお金の動き）

- 請求は、カードごとの締め日・引落日で決まる（三井：月末締め翌月26日、セゾン：月末締め翌月4日。土日祝は翌営業日。設定で変えられる）。
- 確定していない先の請求は保存せず、毎回明細から出す（**請求見込**）。いつものカードの請求見込には、その月の予算残額を足す（予算を使い切るまでは予算の額、こえたら使った分）。確定したら（メールの額・引き落とし済み）口座明細として保存し、見込みではなくなる。v4 と同じ。

## 4. 画面

### 4.1 画面の決まり

1. **計算した数字は、タップすると内訳が出る。** 説明文は置かない。かわりに式と実際の数字を出す。
   ```
   余裕額 ¥52,000 ＝ 手元資金 ¥310,000 ＋ 未入金給与 ¥250,000 − 支払予定額 ¥420,000 − 確保額 ¥88,000
   ```
   式の中の名前もタップでき、その中身の行（どの請求・どの予定か）まで追える。**画面に出る計算した数字は、例外なく全部この形でたどれる。**
2. **1つの表には1種類のデータだけ**を並べる（クレカ明細と口座明細を同じ表に混ぜない）。例外は見通しの「これからの入出金」だけ（残高を日付の順に足し引きするため）。
3. **保存した記録と、アプリが計算しただけの見込みは、見た目で区別する**（見込みは点線の枠と「見込」の印）。
4. 名前は用語表（§6）の熟語にそろえる。画面と内訳で同じ名前を使う。
5. 金額は頭に ¥ をつけて右寄せ。

### 4.2 画面の一覧

| 画面 | 中身 |
| --- | --- |
| **ホーム** | ① 今月の予算残額（大きく）② 費目別残額（こえた費目は赤）③ 最近の明細（メールから入ったものに印。取り込みの確認用）④ 余裕額（小さく）⑤ 使ったものを入れる |
| **明細** | 「クレカ明細｜口座明細」を切り替える。費目ごと／日付ごと。タップで直す・消す。リボに回す（クレカ明細） |
| **見通し** | 線グラフ：口座残高と余裕額。過去は実際の動き、先は見込み（給与・賞与・予定を入れて計算。予算どおりに使う前提）。賞与で返した後の余裕額の見込みが先に見える。その下に、これからの入出金 |
| **計画** | 計画の一覧（目標額・期日・積立額・そろうか）、借入残高、取崩順。計画の中身：毎月の積立額・余裕額から入れる・賞与からの配分・借入残高の更新・リボの返済 |
| **設定** | 予算（月の予算・費目別の予算・目安額の内訳）・給与と賞与・定期・カード・お店のルール・区分・データ（Claude との相談の取り込み） |

### 4.3 予定を入れる画面

保存する前に、入れたら何が変わるかを出す。

- 余裕額 ¥A → ¥B
- その月の予算残額 ¥C → ¥D（足りなければ「余裕額から足しますか？」）
- この先、口座残高が一番少なくなる日と額

保存しなければ何も変わらない（試すだけなら閉じればよい）。

## 5. Claude との相談

仕組みの流れは v4 のまま：アプリが書き出す → GAS が Google ドライブに置く → Claude が読む → Claude が相談の結果を JSON にする → 本人がアプリで確かめて実行。

変えるところ：

1. **書き出しに内訳を入れる。** アプリのタップで出る内訳と同じ式と数字を入れ、Claude が同じ言葉で説明できるようにする。
2. **取り込みでできることを、画面の操作と同じにする。** 計画の作成・毎月の積立額・賞与からの配分・リボに回す・取崩順・予算に足す も Claude から提案できる。画面の操作と同じ名前を使う。
3. **取り込む前の確認に、余裕額などがどう変わるかを出す**（予定を入れる画面と同じ「¥A → ¥B」）。
4. 書き出しの形式名は新しくする（v4 の `gholdengo-snapshot-v1`・`gholdengo-ops-v1` から版を上げる）。`docs/OPS.md` も書き直す。

## 6. 用語表

画面・内訳・仕様書・Claude との書き出しで、同じ名前を使う。

| 名前 | 意味 | v4 での名前 |
| --- | --- | --- |
| 手元資金 | 口座残高 ＋ 財布残高 | （なし） |
| 口座残高 | 口座にあるお金 | 口座残高 |
| 未入金給与 | 今月の給与のうち、まだ入っていない分 | （なし） |
| 未回収立替 | 立て替えて、まだ返してもらっていない額 | （立替の返金の予定） |
| 支払予定額 | 出ていくことが決まっているお金の合計 | （なし） |
| 確保額 | 返済以外の計画の積立額の合計 | 確保額（意味が変わる） |
| 余裕額 | 決まった使い道がないお金 | 予備（確保額の内訳）に近い |
| 予算 | その月に使う額 | 今月の予算 |
| 予算残額 | 予算のうち、まだ使っていない額 | 残り予算 |
| 費目別残額 | 費目ごとの予算残額 | 費目ごとの残り |
| 目安額 | 給与の見込み − 固定費 − 借入の毎月の返済 − 計画の毎月の積立額 | 目安 |
| 予備 | 予算のうち、費目に割り当てていない枠 | 予備（予算の中） |
| 計画 | 目標額・期日を持つ入れ物（返済・購入・貯蓄） | 計画 |
| 目標額 | 計画でためる額 | 使う額 |
| 積立額 | 購入・貯蓄の計画にたまっている額（返済の計画は持たない） | たまる額 |
| 期日 | 計画のお金を使う日・まとめて返す日 | 使う日 |
| 配分 | 賞与などから計画に入れると決めた額 | 賞与から（確保額に入れる分） |
| 借入残高 | リボなど、借りているお金の残り | 残高（計画の中） |

| 取崩順 | 余裕額がマイナスのとき、確保額から差し引く計画の順 | （なし） |
| 取崩不可 | 自動では差し引かない計画の印 | （なし） |
| 請求見込 | まだ確定していないカードの請求 | 請求の見込み |
| 予定・確定 | 明細の状態 | 予定・確定 |

v4 の「実質残高」「確保額＝給料日前日の口座残高」「確保額の内訳の予備」は使わない（余裕額に置き換わる）。

## 7. 作り方

### 7.1 選んだ案：A（土台を残して、計算と画面を入れ替える）

| 案 | 中身 | 取ったか |
| --- | --- | --- |
| **A. 土台を残して入れ替える** | スマホのアプリ・Supabase・ログイン・GAS のメール取り込み・重複をまとめる処理・お店のルール・明細の表（口座明細・クレカ明細）は残す。計算・計画と借入の表・全画面・Claude との書き出しと取り込み・仕様書は作り直す | **取った。** 問題なく動いている部分を活かし、分かりにくさの原因（計算と画面）は全部作り直せる。12月に間に合わせやすい |
| B. 全部新しく作る | 白紙から作る | 取らない。取り込み・重複の処理・ログイン・オフライン表示も作り直しになり、同じ失敗をもう一度つぶす手間がかかる（2〜3週間）。12月の前に数字を確かめる時間が減る |
| （落とした）v4 に余裕額を足していく | | 継ぎ接ぎを重ねることになり、分かりにくさの原因が残る |

### 7.2 決まっている制約

- Supabase はプロジェクト porygon-works の `ggmg` スキーマ。新しい表も `ggmg` に作る（`public` は使わない）。
- 計算は `src/engine/` だけで行う。画面は計算しない。計算は Vitest でテストする。
- お店→費目の正規化は `src/engine/rules.ts` と `gas/Code.gs` の両方にある。変えるときは両方直す。
- リポジトリは公開。家計のデータはコミットしない。テストの値は作り物。
- 確認：`npm run typecheck && npm test && npm run build`。
- 作っている途中も v4 は使い続けられること（切り替えまで、いまのデータを壊さない）。
- 目安：1段階1〜2時間で10段階前後、本人が毎日確かめれば1週間ほどで切り替える。最初の数段階で「予算残額と余裕額が正しく出る」ところまで行く。
- 古い計算（v4 の確保額・予備・実質残高など）と古い画面は、残さず消す段階を計画に入れる。

### 7.3 データ

- 残す：口座明細・クレカ明細・定期・お店のルール・残高の記録・設定・予算・月の予算・要確認・書き出し。
- 作り直す：計画・借入・配分・取崩順の表。v4 の計画（`plans`・`plan_debts`・`plan_funds`）からは写さず、切り替えのときに手で入れ直す（計画は数件のため）。
- 賞与は口座明細の入金として持ち、大費目に「賞与」を足す。**確定は入金されたとき**（額だけ先に分かったら、予定の額を直す）。
- 切り替えのとき、v4 の計画から作った口座明細（`plan_id` のある行）は、予定のものを消し、確定したものはつながりを外して普通の明細として残す。クレカ明細の「分割（購入）」は「リボに回した明細」として引き継ぐ。「分割（返済）」の行は過去の記録として残し、計算には使わない（返済は借入残高で数える）。

## 8. 作らないこと

- 銀行口座の入出金の自動取り込み（通知メールがないため）。
- PayPay のチャージの自動取り込み（手で入れる）。
- 2人以上での利用。
- 説明文をあちこちに書いて、分かりにくさを埋めること（内訳をタップで見せる）。
- 余裕額から予算を通さずに直接使う道（使うお金は必ずどこかの月の予算に入れる）。
- 確保額の中の「予備」（余裕額に置き換わる）。
- 予算の区切りを給料日（15日〜14日）に合わせること（暦の月のまま）。
- 給与の先食いをやめるための専用の機能（貯蓄の計画で表す）。
- 費目の使いすぎを予備から自動で埋めること。
- 名前に文の形の言葉を使うこと（熟語にそろえる）。
- 過去の日の値を、その日の時点の記録として保存しておくこと（過去のグラフはいまの記録から計算し直す）。

## 9. あとで見直すかもしれないこと

- 返済の計画に積立額を持たせない（§3.3）：本人は「いったん A」と決めた。実際の計画の画面ができた段階で見てもらい、分かりにくければ設計書を直してから作り直す。

## 10. 作る人に任せること

- 表の列の名前と、新しい表の作り方（migration の分け方）。
- 内訳をタップで見せるときの見た目（下から出る板・その場で開く など）。どの画面でも同じ形にすること。
- グラフの期間の切り替え（v4 の1か月・3か月・全部を引き継いでよい）。
- 書き出しの JSON の細かい形（用語表の名前を使うこと）。
- 段階の分け方（計画書で決める）。
